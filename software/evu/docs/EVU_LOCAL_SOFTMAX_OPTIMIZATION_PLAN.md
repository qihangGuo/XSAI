## 1. 修改边界

本轮只考虑 EVU 本地调度、操作数收集和访存仲裁。生产代码范围限制在 `src/main/scala/xiangshan/evu/`，测试位于 `src/test/scala/evu/`，文档位于本目录。即使在该目录内，也不推进 CPU 预检接口或指令语义的改造。

保持以下条件不变：

- DLEN/MLEN = 512 bit，VLEN = 4096 bit，32 个向量寄存器，共 16 KiB VRF。
- 32 个物理 64 深度、64 bit 数据宽度的 SRAM bank，每个 bank 保持 1RW。
- `memoryCommandDepth=4`，8 个物理访存 tag。
- CPU 译码、执行写回接口、ROB、AMU 退休路径、MemBlock 和地址预检机制。
- XSAICache/HBL2 功能与协议、CUTE 功能和矩阵连接接口。
- 指令编码、数值语义、浮点舍入、归约算法、WAIT/FENCE 和真实写 Ack 完成边界。
- 主性能测试软件和 bin；不通过改变负载或计时口径取得表面加速。

当前工作区包含此前预检和访存完成路径的修改，其中有 `MemBlock.scala` 等范围外文件。本计划不撤销这些既有修改，也不继续修改这些文件；下一轮新增差异应单独核对。

“只改 EVU”不等于只影响 online softmax：FlashAttention 和其他 EVU 程序也使用这些公共路径，仍须回归。如果实现某项优化必须修改控制核或 CUTE，则暂停该项并重新确认范围。

解读时必须遵守：

- 除 FMA 的“发射 / 有工作未发射 / 无工作”这组三分统计外，不应把表中等待计数当成互斥时间相加。

- `queueIdle` 不能直接证明存在可立即发射的年轻独立指令，需补充上下文和候选就绪信息。
- VMU `ack` 表示至少一个事务正在等待响应，不表示整个 EVU 停顿。
- 本次 GOOD TRAP、`err=0`、difftest `pending=0`；但 `check=0`，不等于独立数值参考检查通过。

## 3. 第一项：提高现有 FMA 的上下文利用率

### 依据与目标

[backend/Backend.scala](../../../src/main/scala/xiangshan/evu/backend/Backend.scala) 当前为 FMA/CMP 分配一个普通上下文和多个归约上下文；[IssueQueue.scala](../../../src/main/scala/xiangshan/evu/backend/IssueQueue.scala) 仍按队首出队。普通操作等待数据时，其他独立行可能没有上下文可以进入。

目标是减少已有工作不能使用 FU 的空拍，不增加 FMA 算术通路数量，也不改变每个操作的浮点步骤。

### 实施内容

1. 在现有 FENCE 快照中补充 EVU 本地诊断：普通上下文忙导致的队首停顿、归约上下文忙导致的停顿、普通/E0 操作的操作数等待，以及存在已就绪独立候选但无法进入上下文的事件。诊断逻辑在正式面积导出时排除。
2. 若确认普通上下文占用限制独立工作推进，先仅为 FMA 增加第二个共享原 FU 的普通上下文，不同时扩展 CMP/EXP2。
3. 为多个上下文保留独立 VAT/年龄、EG 进度和操作数有效状态；继续使用现有共享发射仲裁和结果写回预约。
4. 若采用专用 E0 上下文，必须同时检查队首长向量是否挡住 E0。不能仅新增一个永远接不到命令的上下文；若需要跳过队首，必须保留被跳过指令的 RAW/WAR/WAW 约束。

主要涉及 `backend/Backend.scala`、`backend/ExecuteSequencer.scala`、`backend/SharedExecutionArbiter.scala`；必要时涉及 `backend/IssueQueue.scala` 和 `common/Parameters.scala`。不复制或扩大物理 SRAM 端口，不默认加深结果缓冲。

增加上下文仍会增加寄存器、选择器和依赖比较逻辑，并可能加剧 VRF 竞争。若总周期没有稳定改善，不能仅凭发射率提高保留这部分面积。

## 4. 第二项：兼顾关键加载与存储完成的仲裁

### 依据与目标

当前 [EvuVmuRequestArbiter.scala](../../../src/main/scala/xiangshan/evu/EvuVmuRequestArbiter.scala) 在窗口压力较高时，将等待存储的让行阈值从 8 次成功 load grant 缩短为 2 次；已完成 RMW 读的 Put 也有优先权。这改善了入口阻塞，但尚不能证明优先级始终有利于计算关键链。

first=0 有额外旧 max/sum 读取，且 FMA 等待加载依赖计数为 380。应检查旧状态加载是否被存储优先推迟，不能直接把其微小退化归因给该仲裁。

### 实施内容

1. 统计 load/store 同时就绪时各自获准、因优先级等待、请求年龄，以及“已有计算正在等待该 load 目的 EG”的事件。
2. 只在现有依赖和地址排序检查已允许发出的候选之间仲裁。若证据成立，允许阻塞老计算的加载获得有限优先权，同时保留存储的有界等待保护。
3. 关键加载标记必须匹配真实生产者归属及 VAT/EG，不能仅按寄存器号或 opcode 猜测；若现有接口不足，先用年龄策略，不引入跨 CPU 的新信号。
4. 保留 prepared RMW Put 的推进机会、真实 Ack 完成、tag/job/epoch 归属和 flush 后已发事务排空。下游背压不能消耗成功发射次数预算。

主要涉及 `EvuVmuRequestArbiter.scala`、`EvuVectorBackend.scala`，必要时涉及 `backend/Backend.scala`、`EvuVmuLineCoalescer.scala` 和本地性能接口。

验收同时看 first=0/1 总周期、计算等加载、存储年龄、入口阻塞和 Get/Put 数量。仲裁会改变合并机会，因此不能只比较一个 stall 计数，也不能通过让存储长期积压换取短期发射率。

## 5. 第三项：针对真实等待调整 VRF 读取调度

### 依据与目标

VRF 响应等待仍较高，但当前 `demandPrefetchWait=0`，没有证据说明预取挤占需求读取。完整 EG 转发命中为零，也不足以证明应扩容或删除转发路径。

目标是改善已就绪操作取数，不改变物理 bank 布局、1RW 属性或现有下一 EG 缓冲深度。

### 实施内容

1. 将需求读被其他需求读阻挡、被写预约阻挡、已发 SRAM 读等待返回、返回后消费者尚未就绪分开观察，并保留 FU/普通/E0/归约类别。
2. 若发现已就绪的老操作或归约收尾/E0 读取反复失去仲裁，可在需求读取内部增加有界年龄或关键操作优先，避免让其他向量行饥饿。
3. 继续让需求读取优先于预取；保留现有预取和独立操作数收集。不能仅因总等待高就增加端口、缓冲或预取深度。
4. 对零命中的完整 EG 转发先区分消费者尚未进入上下文、结果已写回及不满足完整 EG 条件，不新增宽结果缓存来猜测解决问题。

主要涉及 `backend/RegisterFile.scala`、`backend/ExecuteSequencer.scala`，以及 `backend/Backend.scala` 的本地接线和计数。需求读加速不能破坏同 bank 读写互斥、操作数版本或预取失效规则。

## 6. 明确暂缓的工作

### CPU 执行端与地址预检解耦

暂不实施。普通 EVU load/store 仍有 `noSpec/blockBack`，单加两个缓冲项不能保证后继命令实际到达。完整实现需要同步处理 CPU 译码、ROB 屏障、异常信息归属、配置快照、分支取消和地址空间稳定性，超出本轮 EVU 本地范围。

当前 CPU 预检等待 2,270/1,817 周期作为已知限制保留，不能宣称本轮 EVU 内部优化能够全部回收。

### LAUNCH、mmacc、量化和反量化编程模型

暂不实施接口重构。后续设计方向为：普通 mmacc 独立更新 acc；需要直通的任务显式绑定结果导出描述符和带代际信息的任务 token；配置完成、计算完成和最终内存 Ack 完成分别定义。量化直写 CUTE 保留明确目标和数值语义。

这些工作需要 CPU/EVU/CUTE 接口、NEMU 和软件协同修改，不应夹带在本轮性能补丁中。当前纯 online softmax 不使用 CUTE、LAUNCH 或量化通路，接口重构不会直接改善该测试。

此外，本轮不改接 L1，不修改 HBL2 带掩码写，不扩大 DEPTH、DLEN 或 VRF，不新增 EXP2/FMA 算术单元，不新增跨命令数据缓存。

## 7. 实施顺序与验收

1. 保留当前日志和软件 bin，记录 RTL 差异、配置及 bin 校验值。当前文档的基线是 6,652/5,353，不是前一轮的 6,600/5,536。
2. 先补最少的区间诊断并确认 FMA 上下文瓶颈；条件满足才实施第一项功能改动。随后评估仲裁，最后处理仍然突出的 VRF 读取等待，不一次叠加三项无法归因的修改。
3. 对新增上下文验证跨行 RAW/WAR/WAW、同寄存器重用、E0 与整 EG 混合、归约、尾部及掩码、不同流水延迟的结果冲突；对仲裁验证公平性、背压、RMW、最终 Ack、flush 和 FENCE。
4. 在服务器使用同一份主 bin、同一 NEMU 和完成计时边界复测 first=0/1，比较正式 FENCE 区间，不以预热、诊断 `pre/full` 或 host time 替代内核 `c`。同配置重复运行，并记录可重复性，不把单次小波动直接归因。
5. 继续运行向量基础算子、存储/状态微测试和 FlashAttention difftest。独立正确性模式作为额外回归，不替换主性能 bin；纯调度修改不应要求修改 NEMU 语义。
6. 比较 FlashAttention 时保持输入规模、预热和软件优化开关一致。仅改善 softmax 而明显损害其他 EVU 工作负载的策略需要调整，不能只挑选有利用例。
7. 接受标准是正确性通过、主内核总周期有可重复收益且无不可接受的回退，同时检查逻辑规模和时序风险。计数下降不等于收益，仿真周期改善也不代表物理频率已验证。

本机只做源码/文档检查与日志解析，不生成 RTL、不运行 emu、不生成 bin，也不启动 Java/Mill 构建。需要的综合、回归和 emu 构建由服务器执行。本计划不预先承诺新的周期目标。
